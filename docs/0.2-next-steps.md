# 0.2-next-steps: Implementation Roadmap for Stack Switching

Status: Draft

Overview
--------
This document is a concise, staged implementation plan for completing the stack-switching feature described in `0-tinywasm-ssw.md` and already partially implemented in `tinywasm-ssw`.  It addresses outstanding gaps, recommended engineering tasks, tests, validation, host-function integration, and CI updates.

Goals
-----
- Complete runtime semantics for the core Stack Switching instructions (cont.new/cont.bind/suspend/resume/switch/resume.throw).
- Add and complete parser/resume-table handling and type-checking.
- Implement tag and value passing semantics for suspend/resume/switch/resume.throw.
- Add host integration: mark host functions suspend-aware; add resume handlers if needed; verify suspend/resume inside host calls.
- Add a comprehensive test suite (parser, unit, integration, WAT/WAST) and CI gating for feature `stack-switching`.
- Provide documentation and example WAT programs demonstrating stack-creation, bind, suspend, resume, and switch.

High-level Approach
-------------------
- Implement features behind `stack-switching` cargo feature guard.
- Keep changes small and incremental; do not alter existing non-stack-switching behavior.
- Implement test-first where feasible (parser tests, simple runtime tests).

Phases & Tasks (incremental, small crunchable commits)
----------------------------------------------------

Phase A — Parse & metadata
  1. Persist `resume_table` and tag/type metadata in the function/module representation
     - Files: `crates/parser/src/visit.rs`, `crates/types/src/lib.rs`, `crates/types/src/instructions.rs`.
     - Task: Update `visit_resume` / `visit_resume_throw` to store the `ResumeTable` and collect tag types. Add fields in `WasmFunctionData` to hold resume tables per-func (or an indexed table keyed by `cont_type_index`).
     - Tests: Parser tests that validate a module with `resume`/`resume.throw` operators and assert the resume table types are preserved.
     - Acceptance: Parser builds resume metadata and still respects wasmparser Validator.

  2. Add validation checks in parser for illegal patterns
     - Files: `crates/parser/src/visit.rs` / `module.rs` validator stage
     - Task: Add validation to reject invalid use of stack-switching ops based on basic constraints uncovered in proposal (e.g., correct tag types, resume table entry correspondence, disallow resume in host function if missing support).
     - Tests: Positive & negative WAT testcases.

Phase B — Value & tag handling
  1. Add typed tag structures & helpers
     - Files: `crates/tinywasm/src/store/stack.rs`, `crates/types/src/lib.rs` (tag types, cont type defs), `crates/tinywasm/src/interpreter/executor.rs`.
     - Task: Implement `TagValue` typed container (already has `TagValue`) and wire in the typed schema (tag type -> expected types of values). Ensure `WasmValue`/`TinyWasmValue` conversions and safety.
     - Acceptance: `exec_suspend` and `exec_resume` push/pop typed values accordingly.

  2. Implement tag-based value transfer between stacks
     - Files: `crates/tinywasm/src/interpreter/executor.rs` (exec_suspend, exec_switch, exec_resume), `crates/tinywasm/src/store/mod.rs` (store the tag values or resume table mapping), `crates/tinywasm/src/store/stack.rs` (Store `SuspendContext` with typed `TagValue`).
     - Task: Update `exec_suspend`/`exec_switch` to collect and persist the correct typed values based on the `tag_index` and recorded types; update `exec_resume`/`exec_resume_throw` to place those values onto the resumed stack's value stack (with type conversion / validation).
     - Tests: Validate typed values are passed correctly; validate invalid type cases trap.

Phase C — cont.bind implementation
  1. Implement `cont.bind` semantics
     - Files: `crates/tinywasm/src/interpreter/executor.rs`, `crates/tinywasm/src/store/stack.rs`.
     - Task: Implement capturing N args for a continuation and storing them in the continuation's initial locals or a bound continuation wrapper. Decide how to represent bound continuations (new continuation ID vs reuse store slot?).
     - Tests: `cont.bind` should allow pre-binding args and match expected behavior: `resume` receives those bound args in addition to resume ctx values.

Phase D — resume.throw & exception semantics
  1. Implement resume.throw semantics
     - Files: `crates/tinywasm/src/interpreter/executor.rs`, `crates/tinywasm/src/store/stack.rs`.
     - Task: Implement throw semantics to propagate an exception/tag across stacks, respecting tag types and ensuring unwinding (trap) or handler invocation is properly implemented. Add necessary exception-handling instructions if missing.
     - Tests: `resume.throw` with tag args should trigger handlers or trap as required in the proposal.

Phase E — Host integration & validation
  1. Make host functions suspend-aware
     - Files: `crates/tinywasm/src/imports.rs` and `crates/tinywasm/src/interpreter/executor.rs` (host call impl), and `docs/stack-switching-host-integration.md`.
     - Task: Add a marker to host functions to indicate if they support suspension; update host call paths to track suspension state and enable `exec_suspend` & `exec_resume` in this context if allowed.
     - Tests: Host-function suspension/resume. Validate that resuming into host function contexts behaves per proposal.

  2. Add runtime validation and safer checks
     - Files: Parser and Executor
     - Task: Add runtime checks and traps for illegal operations (e.g. resuming a `Dead` or `Running` continuation, cross-module disallowed resumes, resuming a continuation that was created by a different module if disallowed by spec).
     - Tests: Invalid resume / protection tests.

Phase F — Resource Limits & Safety
  1. Per-cont stack limits and traps
     - Files: `crates/tinywasm/src/interpreter/stack/*`, `crates/tinywasm/src/store/mod.rs`.
     - Task: Add stack size checks per `StackConfig`, guard `call_stack` growth, trap appropriately.
     - Tests: stack overflow triggers a trap.

Phase G — Tests & CI
  1. Add parse-only tests in `crates/parser/tests`
     - Testcases for `cont.new`/`cont.bind`/`suspend`/`resume`/`switch` parsing and `resume_table` metadata.

  2. Add runtime integration tests in `crates/tinywasm/tests` and `crates/tinywasm/tests/generated` with WAT/WAST
     - Minimal happy-path examples: create 2 continuations, switch between them, suspend/resume values, cont.bind, resume.throw.
     - Negative testcases: resume dead continuation, resume wrong type values, resume across modules when disallowed.
     - Host testcases: suspend/resume from inside host functions and resume into host functions.

  3. Add a feature gated CI job in `.github/workflows/*` to run `stack-switching` tests
     - Ensure default CI runs minimal tests; add optional job to run feature on nightly or special matrix.

Phase H — Docs, examples, and housekeeping
  1. Update `docs/stack-switching-host-integration.md` with concrete examples and host API suggestions.
  2. Add an example `examples` module demonstrating a standard `cont.new` / `switch` / `resume` flow and one showing host integration.
  3. Add change logs and update `README` for the `stack-switching` feature.

Detailed Implementation & Edges (Engineer’s checklist)
-----------------------------------------------------
- `cont.new`:
  - Create stack for function reference. The initial stack must contain a first (entry) call frame with correct signature (params/results maybe empty) and locals.
  - Be explicit: stacks created by `cont.new` start `Suspended`, not `Running` — ensure `StackInstance::new` sets `Suspended`.

- `cont.bind`:
  - Decide representation: bound continuation (new Id) vs in-place mutation (replace locals) — leaning towards producing a new bound continuation object for clarity.
  - Implement `argc` & `result` binding: pop arguments off the *current stack* in correct order and store them at the front of the target continuation's local or params list.
  - Validate arg types vs expected cont types.

- `suspend`/`switch`/`resume`/`resume.throw`:
  - Use the tag index to determine values to transfer (use typed `TagValue`). Validate types & push onto destination stack.
  - After swapping, add a return/address reference on the destination stack so resuming back is possible if semantics require it.
  - The `return_addr` should be a `ContAddr` stored in `SuspendContext` for `switch` semantics.
  - `switch` must be bidirectional (source becomes suspended with a `return_addr` that returns to previous stack).

- `resume_throw` semantics:
  - The resumed stack should get a thrown exception. If the exception isn't handled, it should unwind similarly to a normal trap, but with tag semantics; check the proposal’s exact mechanics.

- `ResumeTable` handling:
  - `ResumeTable` indicates where the resumed values will appear (the intrinsics for `resume` and `resume.throw`); ensure resume table is preserved and used for type validation.

- Host functions:
  - Add a field to host `FunctionInstance` descriptor: `suspend_aware: bool`.
  - The `exec_call_host` path must check `host_func.suspend_aware` or provide a procedure to register resume callback.
  - If host functions are not suspend-aware, enforce validation errors/traps when suspend/resume occurs inside them.

- Safety & Ownership:
  - Avoid concurrency assumptions: single-threaded for now.
  - Implement `Store` stack ops with `Option::take()` pattern to avoid borrows.
  - Use `get_pair_mut()` if needed to get two mutable stacks while avoiding borrow conflicts.

Testing Strategy (detailed)
---------------------------
- Parser tests (unit): Add tests covering `cont.new`, `cont.bind`, `suspend`, `resume`, `resume.throw`, `switch`, and `resume_table` handling.
- Short runtime tests (unit): Use `execmute` harness to call a small snippet to validate that the correct trap or return value occurs for simple flows.
- WAST tests: Add small runnable WAT files that:
  - Create two continuations, switch between them, and validate locals/value stacks persist.
  - Bind a continuation, resume it and confirm bound args are observed.
  - suspend/resume passing tag values across continuations.
  - resume.throw raising the correct exception handler.
  - Host function suspend/resume testing: create a host function that is `suspend_aware` and test suspend and resume.
- Negative tests: Resume Dead/Running conts; incorrect typed values; resume across modules if invalid.

Acceptance Criteria
-------------------
- Parser: `stack-switching` feature enable toggles parsing and validation of `cont.*` ops and resume tables.
- Types: Resume tables & tag type metadata preserved in `WasmFunctionData` and available to the runtime.
- Runtime: `cont.new`, `cont.bind`, `suspend`, `switch`, `resume`, `resume.throw` operate in typical scenarios and preserve frames & values.
- Host functions: Host integration supports suspension (when host marks itself `suspend_aware`), or suspends with explicit validation errors otherwise.
- Tests: New tests exist in parser and runtime; CI has a feature-gated job to run stack-switching tests.
