# Process spawning in WASM: investigation and patch plan

## Summary (short) ✅
- **Problem**: The current codebase relies on synchronous blocking I/O (`read_to_string`, `wait()`) and threading (`spawn_blocking`), which causes deadlocks in the single-threaded WASM environment.
- **Solution**:
    1.  **VFS Bridge**: Implement a `/dev/host/process/<pid>` protocol for spawning and managing processes via the host.
    2.  **Hard Rewrite**: Rewrite `brush-core/src/commands.rs` to use `tokio::spawn` (tasks) instead of `spawn_blocking` (threads) and async I/O.
    3.  **Stubs**: Patch `sys::stubs::process` to use the VFS bridge.
    4.  **Defer**: Disable or stub complex coreutils (`timeout`, `stdbuf`) for now.

## Proposed Design / Protocol (VFS-based) 📡

### 1. The VFS Bridge: `/dev/host/process/<pid>`

Instead of a flat spawn directory, we use a directory-per-process model to manage state.

**Spawn Request:**
Guest writes a JSON request to `/dev/host/process/spawn.json`.
```json
{
  "program": "ls",
  "args": ["-l", "/"],
  "env": { "KEY": "VALUE" },
  "cwd": "/workdir",
  "fds": { "0": "inherit", "1": "pipe", "2": "pipe" }
}
```

**Host Response:**
Host creates a directory `/dev/host/process/<pid>/` (where `<pid>` is a host-assigned ID) and populates it with:
*   `stdin` (writable file, if piped)
*   `stdout` (readable file, if piped)
*   `stderr` (readable file, if piped)
*   `status` (readable file, contains exit code/signal when done)
*   `signal` (writable file, for sending signals like SIGKILL)

**Guest Handling:**
*   `spawn()` writes the request and reads the response (which contains the `<pid>`).
*   `Child` struct holds the `<pid>`.
*   `wait()` polls `/dev/host/process/<pid>/status`.
*   `read()` reads from `/dev/host/process/<pid>/stdout`.

### 2. The "Hard Rewrite": `brush-core/src/commands.rs`

The function `invoke_command_in_subshell_and_get_output` is the primary blocker. It must be rewritten to be fully async.

**Current (Blocking):**
```rust
let (reader, writer) = std::io::pipe()?;
let handle = tokio::task::spawn_blocking(move || { ... }); // BLOCKS
let output = std::io::read_to_string(reader)?; // BLOCKS
```

**Proposed (Async):**
```rust
// Use async pipe (e.g., tokio::io::duplex or a VFS-backed pipe)
let (mut reader, writer) = tokio::io::duplex(64 * 1024);

// Use tokio::spawn (local task) instead of spawn_blocking
let handle = tokio::spawn(async move {
    // Run subshell logic async
    run_substitution_command(subshell, params, writer).await
});

// Read async
let mut output_str = String::new();
reader.read_to_string(&mut output_str).await?;

handle.await??;
```

### 3. Stubs Implementation (`sys/stubs/process.rs`)

The `sys::stubs::process` module must be patched via `build.rs` to redirect to `stubs_impl`.

*   **`spawn(Command)`**:
    1.  Serialize `Command` to JSON.
    2.  Write to `/dev/host/process/spawn.json`.
    3.  Read PID from response.
    4.  Return `Child { pid }`.

*   **`Child::wait()`**:
    1.  Loop:
        *   Check if `/dev/host/process/<pid>/status` exists.
        *   If yes, read exit code and return.
        *   If no, `yield_now().await` (or sleep).

## Implementation Plan 🛠️

1.  **Host Side (`washm.js`)**:
    *   Implement the `/dev/host/process` VFS provider.
    *   Handle `spawn.json` writes by spawning real processes.
    *   Expose stdio pipes as VFS files.

2.  **Brush Core (`commands.rs`)**:
    *   Apply the "Hard Rewrite" to `invoke_command_in_subshell_and_get_output`.
    *   Ensure `run_substitution_command` is async and takes an async writer.

3.  **Stubs (`stubs_impl.rs` & `build.rs`)**:
    *   Implement `spawn_process` trampoline.
    *   Implement `GuestChild` with async wait/IO.
    *   Patch `sys/stubs/process.rs` to use these implementations.

4.  **Coreutils**:
    *   Disable `timeout`, `stdbuf` in the build configuration for WASM.
    *   Disable `compression` feature in `sort`.
    *   Disable `filter` feature in `split`.
